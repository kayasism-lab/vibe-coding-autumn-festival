# 2026 가을연극축제 사이트 — 현황 평가 및 개발 계획서 (v2)

작성일: 2026-08-15 (v2 전면 개정)
기준 문서: `(260814 보완요청) 159_민간(신규)_가을연극축제(직장인들의 이중생활)_서명란추가_2차보완.hwp`
목적: 서울시 민간축제 보조사업 계획서에 부합하는, 모바일 최적화된 공식 축제 안내 사이트 구축.

> **v2 개정 사유**: 축제 사업계획서(HWP)를 확보해 검토한 결과, 현재 사이트에 표시된 상당수 정보가
> 실제 축제 계획과 **다르거나 존재하지 않는 내용**임이 확인되었습니다. 이는 단순 UI 문제가 아니라
> 보조사업의 대외 신뢰도와 직결되는 문제이므로, 계획서 전체를 다시 작성했습니다.

## 3. 문제점 진단

### A. [치명적] 사이트 콘텐츠가 실제 축제와 다름 → **0장 참조**

### B. [심각] 핵심 기능(일정·예약)이 DB와 연결되어 있지 않음

| 파일 | 문제 |
|---|---|
| `frontend/app/schedule/page.tsx` | 9~11월 일정이 소스에 배열로 하드코딩(`scheduleData`). 백엔드에 `GET /api/schedules`가 완비되어 있는데 미사용 |
| `frontend/app/tickets/page.tsx` | 예매 정보(`ticketInfo`) 하드코딩 + **존재하지 않는 유료 가격·할인 제도** 표시 |
| `frontend/app/programs/[id]/page.tsx:125` | "공연 일정" 값이 `"관리자 입력 일정"` 플레이스홀더 문자열 |

→ 관리자가 `/admin/schedules`에 일정을 등록해도 방문객은 볼 수 없음.

### C. [심각] 극단 정보 공개 페이지 부재

`TheaterGroup` 모델과 관리자 CRUD는 완비되어 있으나, 방문객용 독립 페이지가 없습니다.
홈 히어로 섹션의 모달 팝업이 유일한 노출 지점이며, 헤더 메뉴에도 없고 고유 URL도 없어
**공유·검색 노출·딥링크가 모두 불가능**합니다.

### D. [신규] 시민 참여 신청 창구 부재

계획서상 홈페이지가 열린 낭독극·열린 단막극의 **공식 공개모집 창구**인데, 현재 `/apply`는
극단 단위 참가신청(극단명/대표자/작품명/러닝타임 등) 폼이라 개인 시민이 쓸 수 없습니다.

## 4. 개선 목표

1. **사이트 정보를 실제 축제 계획서와 100% 일치**시킨다. (최우선)
2. 관리자가 입력한 데이터가 방문객 화면에 그대로 반영되도록 API 연결을 완성한다.
3. **"무료 + 시민 누구나 참여 가능"**이라는 축제 정체성이 첫 화면에서 전달되게 한다.
4. 주최·후원 기관을 공식적으로 노출한다.
5. 극단이 준비 과정(영상·사진)을 스스로 올리고, 방문객이 그 과정을 볼 수 있게 한다.
6. 모바일에서 3초 안에 "무엇을·언제·어디서·어떻게 예약"을 파악할 수 있게 한다.

## 5. 단계별 개발 계획

### Phase 0 — 콘텐츠 정정 (최우선, 다른 모든 작업에 선행)

가짜 정보를 걷어내는 단계입니다. 코드 난이도는 낮지만 영향도는 가장 큽니다.

1. **유료 티켓·할인 제도 전면 제거**
   - `app/tickets/page.tsx`: 가격표·할인 안내(학생 25%, 시니어 25%, 장애인 50%, 국가유공자 50%) 삭제.
   - 페이지 성격을 「예매 안내」→ **「관람 안내 / 무료 예약」**으로 전환.
   - `Program` 모델의 `price` 필드는 스키마상 `required`이므로, 무료(0원) 처리 또는
     `isFree` 플래그 추가 여부를 백엔드에서 결정 (권장: `price.regular` 기본 0 + 화면에 "무료" 표기).
2. **축제 기본 정보 정정**
   - `components/home/countdown-section.tsx`: `FESTIVAL_START`를 **2026-09-19**로 수정
     (이후 Phase 5에서 SiteConfig 연동).
   - `app/layout.tsx` 메타데이터: 부제 「직장인들의 이중생활」, 제24회, 무료, 실제 프로그램 구성 반영.
     현재 "4개의 연극, 1개의 뮤지컬" 문구는 사실과 다르므로 반드시 수정.
   - `app/about/page.tsx`: 축제 개요(기간/장소/프로그램/극단 수), 2001년 창립~제24회 연혁,
     운영위원회(조직위원장 문성환, 사무국장 진주호) 반영.
   - `components/layout/footer.tsx`: 실제 연락처·주소로 교체, SNS는 인스타 `@jikplay1997`,
     홈페이지 `cafe.daum.net/jik` 연결.
3. **가공의 극단·작품·공연장 데이터 제거**
   - `schedule`, `tickets` 하드코딩 배열 삭제(Phase 1에서 API로 대체).
   - `hero-section.tsx`의 `defaultTheaterGroups` fallback은 실제 6개 극단 정보로 정정.
4. **축제 정체성 문구 반영**
   - 히어로 카피를 "관람에서 참여로 이어지는 축제" 메시지로 조정.
   - 통계 카드(현재 "연극 4 / 뮤지컬 1 / 단막극제 1")를 **"연극 2 / 낭독극 1 / 단막극 1"** 또는
     "프로그램 4 · 공연 10회 · 전석 무료"로 교체.

### Phase 1 — 주최/후원 로고 노출 (신규 요청 ①)

계획서상 서울시는 **명칭후원** 기관이므로 표기 의무가 있습니다.

#### 3-2. 공연 준비 과정 영상·사진 (신규 요청 ②)

계획서에도 **영상촬영·편집 예산(2,100천원)**과 부대전시 '연극 전후, 달라진 나'가 있어

**백엔드 — 신규 모델 `RehearsalPost`(가칭) 추가 권장**

```
theaterGroupId: ObjectId (ref TheaterGroup)   // 어느 극단이
programId: ObjectId (ref Program, optional)    // 어느 작품 준비 과정인지
title: String
description: String
youtubeUrls: [String]     // 유튜브 주소 (용량 문제 회피)
imageUrls: [String]       // Cloudinary 업로드 결과 URL
publishedAt / isActive / order
```

- 라우트 `backend/src/routes/rehearsals.ts` 신규 (GET 공개, POST/PUT/DELETE는 권한 필요).

  필요하므로 별도 모델을 권장합니다. (설계 확정 전 기존 `gallery.ts` 스키마 확인 필요)

**사진 업로드 — 기존 Cloudinary 자산 재사용**

이미 `components/admin/cloudinary-upload.tsx`에 업로드 위젯이 완성되어 있습니다
(크롭, 비율 선택, 미리보기 그리드, 다중 업로드, 한국어 UI 모두 구현됨).
`shopping-mall-demo`의 `client/src/utils/cloudinaryWidget.js`와 동일한 Cloudinary 방식이므로
**같은 Cloudinary 계정을 그대로 사용 가능**합니다.

- 필요 작업: `frontend/.env.local`에 `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME`,
  `NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET` 값 채우기 (현재 `.env.example`은 빈 값).
  shopping-mall-demo의 `VITE_CLOUDINARY_*` 값을 그대로 옮기면 됩니다.
- 업로드 폴더는 `autumn_festival/rehearsals/{극단명}` 형태로 분리 권장.
- 참고: shopping-mall-demo 쪽은 위젯 스크립트 URL이
  `upload-widget.cloudinary.com/latest/global/all.js`, autumn_festival 쪽은
  `widget.cloudinary.com/v2.0/global/all.js`로 다릅니다. 동작은 하지만 통일 검토.

**유튜브 영상 — URL 입력 + 미리보기**

- 입력: 관리자/극단이 유튜브 주소를 붙여넣으면 videoId를 파싱
  (`youtu.be/xxx`, `youtube.com/watch?v=xxx`, `youtube.com/shorts/xxx` 3가지 형태 모두 지원).
- 미리보기: 입력 즉시 썸네일(`https://img.youtube.com/vi/{id}/hqdefault.jpg`)을 보여줘
  주소가 맞는지 확인 가능하게 함.
- 재생: 목록에서는 썸네일만 렌더링하고, 클릭 시 `youtube-nocookie.com/embed/{id}` iframe으로
  교체하는 **지연 로딩(lazy) 방식**을 권장 — 모바일 데이터·초기 로딩 속도에 유리.
- 컴포넌트: `components/shared/youtube-embed.tsx`(신규) + `lib/youtube.ts`(URL 파서).

**공개 화면**

- `app/theater-groups/[id]` 하단에 "공연 준비 과정" 탭/섹션으로 영상·사진 노출.
- 또는 `app/rehearsals/page.tsx`로 전체 극단 준비 과정을 모아 보는 페이지도 검토
  (부대행사 '연극 전후, 달라진 나' 온라인판 성격).

**권한 정책 (결정 필요)**
현재 관리자 인증만 존재합니다. "극단이 직접 올린다"를 구현하려면
(a) 극단 계정 개념 신설, (b) 관리자 대행 입력, (c) 극단별 업로드 링크/코드 발급
중 선택이 필요합니다. → **7장 확인 필요 사항** 참조.
