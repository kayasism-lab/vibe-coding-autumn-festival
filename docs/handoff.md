### (4) 극단별 예정 공연정보

극단 소개 팝업에 앞으로의 공연을 알릴 자리가 없던 것을 추가. **극단당 한 건.**

`TheaterGroup.upcomingShow`:
- `kind: 'festival'` — 축제 프로그램을 가리킴(`programId`). **공연일을 저장하지 않고

## 3. 알려진 이슈 / 기술 부채

- **`frontend/app/contact/page.tsx`가 361줄로 프로젝트 300줄 제한을 넘김.** 손대기 전에 이미 332줄이었고 동의 UI 추가로 늘어남. 문의 폼을 별도 컴포넌트로 분리해야 함. 참고로 문의 폼이 `/inquiries/new`와 `/contact` 두 곳에 있고 **같은 API(`POST /api/inquiries`)를 씀** — 아래 9번의 페이지 통합 문제와 같이 정리하면 한 번에 해결됨.
- **개인정보 보유기간(축제 종료일로부터 1년) 자동 파기 기능이 없음.** 처리방침에는 명시했으나 실제로는 관리자가 수동 삭제해야 함. 기간이 지난 신청·문의를 일괄 삭제하는 기능이나 운영 절차가 필요함.

- `backend/src/scripts/seed-admin.ts`가 계정 생성 성공 후 `process.exit(0)`을 호출하지 않아 스크립트가 안 끝나고 멈춤(성공 로그는 찍힘). 아직 코드 수정 안 함, 실행할 때는 성공 메시지만 확인하고 별도 명령으로 넘어가면 됨.
- 헤더 상단 바 크기 관련 값들(`h-11`, 로고 `h-8`/`h-7` 등, 그리고 18개 하위 페이지의 `pt-[8.25rem]`)은 서로 맞물려 있음 — 상단 바 높이를 또 바꾸면 그 18개 파일의 `pt-[...]` 값도 같이 조정해야 레이아웃이 깨지지 않음. 대상 파일 목록은 `grep -rl "pt-\[8.25rem\]" frontend/app`로 확인 가능.

- **`sm:max-w-lg` 함정.** 공용 `Dialog`의 기본 클래스에 이 값이 있어, 팝업을 넓히려고 `max-w-5xl`만 주면 큰 화면에서 512px에 갇힌다(반응형 변형이 이김). 넓은 팝업을 만들 때는 `sm:max-w-none`이나 `sm:max-w-*`를 반드시 함께 줄 것. 갤러리 크게 보기가 이것 때문에 깨져 있었다.
- **기존 갤러리 사진은 2000px로 저장돼 있다.** 저장 크기를 2560px로 올린 것은 앞으로 올리는 사진부터 적용된다. `c_limit`은 원본보다 크게 늘리지 않으므로 화질이 나빠지진 않고 여유분만 없는 상태. 운영에 사진이 몇 장 없어 그대로 두었음.
- **운영 갤러리 자료의 분류가 전부 '기타'다.** 구분·극단을 지정하지 않아서다. 관리 화면에서 골라주면 필터가 제 힘을 낸다.
- **인스타그램 영상은 사이트 안에서 재생할 수 없다.** 임베드가 영상 데이터를 내주지 않는 것을 실제로 확인했다(video 요소는 있으나 duration이 NaN). 대표 이미지를 누르면 인스타로 보내는 방식이며, 썸네일도 자동 추출이 안 되므로 **직접 올리지 않으면 목록에 빈 화면이 보인다**.
- **`sanitize-html` 의존성이 추가됐다** (백엔드). Cloudtype 빌드에서 자동 설치되지만, 설치 실패로 빌드가 깨지면 이 패키지를 먼저 의심할 것.
- `next-env.d.ts`는 dev 서버 실행 시 `.next/types` ↔ `.next/dev/types`로 자동 변경됨. **커밋에 포함시키지 말 것** (프로덕션 빌드에서 문제 소지). 커밋 전 `git checkout HEAD -- frontend/next-env.d.ts`로 되돌리는 게 관행이 됨.
- 프로덕션 빌드(`npm run build`)는 dev 서버가 떠 있는 상태에서 돌리면 Turbopack 캐시가 충돌함(과거 전 페이지 500 발생). **dev 서버를 내리고 빌드 → 끝나면 다시 올릴 것.**
